# 聚合订阅

把几个来源的节点合并成一个订阅，由澜流在本机生成完整的 Mihomo 配置。节点处理、代理组、分流规则、中转组和基础配置都在界面里完成，不需要手写 YAML，也不依赖在线的订阅转换服务。

界面布局参照 [SubBoost](https://github.com/SubBoost/subboost)（subboost.org）的配置生成器：左侧「配置生成器」，分快捷模式与高级模式；右侧「预览」，可切换可视化与 YAML。代码是澜流自己用 Go 写的：SubBoost 与 Clash Party 集成的 [Sub-Store](https://github.com/sub-store-org/Sub-Store) 都是 AGPL-3.0，与澜流的 MIT 不兼容，没有复制任何代码或数据表。

## 1. 用户看到的

- 侧栏「订阅」下方的「聚合订阅」进入聚合订阅页：列出本机生成的每个聚合订阅（来源数、模板、更新时间、流量），每张卡片可以使用、更新、编辑，「⋯」里有编辑覆写、查看配置、删除；右上角「新建聚合订阅」。编辑页在这一页里打开，保存或取消后回到列表。
- 订阅页「导入 ▾ › 新建聚合订阅…」和行菜单「编辑聚合…」也会跳到这一页。聚合订阅同时出现在订阅表格里，可以像其他订阅一样切换。
- 聚合订阅在订阅表格的来源列显示「聚合」，和链接订阅一样可以启用、更新、自动更新、编辑覆写、查看配置。
- 编辑页分左右两栏；窗口宽度不足 1000 时改为页头的「配置 / 预览」切换，点「生成配置」后自动切到预览。

### 1.1 左栏：配置生成器

来源卡片两种模式共用。新建时默认有订阅链接、YAML 配置、节点链接三张空卡片，没填的卡片生成和保存时都会被忽略，至少要填一个。每张卡片头部有四个类型图标（订阅链接、YAML 配置、节点链接、已有订阅）、标题、预览后的「✓ N 节点」或「✕ 失败」（悬停看原因），以及上移 / 下移、展开编辑（大编辑框，另可设显示名称、名称前缀、停用）、解析并预览、删除。卡片下方是虚线的「添加订阅/节点源」。

**快捷模式**

- 来源卡片。
- 「选择模板」：精简版、标准版、完整版三张单选卡片，右侧显示代理组数与规则集数；「我的模板」卡片打开模板列表（套用、删除）。改过代理组后不再标记任何模板，并提示到高级模式里查看。
- 「订阅设置」：名称、自动更新、User-Agent、下载超时、通过代理下载、新建时「导入后立即使用」。

**高级模式**，各区块可折叠，标题右侧有计数：

| 区块 | 内容 |
| --- | --- |
| 节点导入 | 来源卡片 |
| 节点管理 | 搜索；「监听端口」开关与起始端口；「批量编辑」（有序的正则替换，带基于当前节点的预览）；「自动处理」（保留 / 排除正则，每行一条）。预览后列出节点：协议、名称、中转组、监听端口，可上移下移、隐藏 |
| 中转代理组 | 每组：名称、中转节点正则、落地节点正则；「添加中转组」提供香港 / 日本 / 新加坡 / 美国 / 台湾预设和自定义名称 |
| 分流代理组 | 规则来源：自带数据库或远程规则集（可改规则集 URL）；9 类模块（核心组、地区节点、常用服务、社交通讯、流媒体、游戏平台、技术服务、金融服务、其他）各自折叠，模块行有开关和「编辑分组」（改名、改类型）；「自定义分组」可添加名称、类型、节点筛选和规则集 |
| 自定义分流规则 | 方法一：规则库，搜索全部 GeoSite 分类与 GeoIP 国家 / 服务，选好目标代理组后点击添加；方法二：手动添加（类型、值、目标、no-resolve）与批量导入（每行 `类型,值[,目标]`） |
| 规则管理 | 全部规则按最终顺序列出，可上移下移；MATCH 固定最后；「恢复默认顺序」 |
| 基础和 DNS 配置 | 一段 YAML，合并到生成配置的顶层 |
| 订阅设置 | 同快捷模式 |

底部按钮：「生成配置」（下载来源并生成，不保存）、「保存为模板」。

### 1.2 右栏：预览

- 「可视化」：节点 / 代理组 / 规则集三个计数；每个代理组一张卡片，写明类型（手动选择、自动测速、故障转移、负载均衡、拦截、直连）和默认出口，展开可见指向它的规则；最后是节点列表。
- 「YAML」：生成的完整配置，只读。
- 来源失败、警告、订阅流量合计显示在上方；设置改过后提示预览已过时，可「重新生成」。
- 底部「导入澜流」（编辑时为「保存到澜流」）与新建时的「立即使用」：先下载来源、生成配置并用内核校验，通过后才写入；失败时编辑页保持打开并显示原因，原来的配置不变。

## 2. 生成规则

处理顺序：读取来源 → 按原始名称「保留」「排除」→ 重命名规则依次替换 → 合并空白、加来源前缀 → 去重编号 → 按「节点管理」的顺序排列 → 去掉隐藏的节点。

- **来源**
  - 订阅链接：用 `FetchRaw` 下载（不要求是 Clash 格式），内容可以是 Clash/Mihomo 配置（取 `proxies`；`proxy-providers` 里的节点并不进来，给出警告），也可以是分享链接列表，原文或 Base64。并行下载，使用订阅自己的 User-Agent、代理与超时设置。
  - YAML 配置：用户粘贴的 Clash/Mihomo 配置，同样取 `proxies`。
  - 节点链接：用户粘贴的分享链接，解析复用手动节点的 `parseNodeURI` 与 `BuildManualProxyNode`，协议范围与「添加节点 › 导入剪贴板」一致，另外支持 `ssr://`（生成 `type: ssr` 节点；Mihomo 没有 socks4 出站，所以不支持 `socks4://`）；不认识的行计入「无法识别」。也可以粘贴 Clash YAML 格式的节点：单个节点、节点列表（`- {name: …, type: ss, …}`）或带 `proxies` 的配置，还可以和分享链接混在一起，以 `scheme://` 开头的行按链接解析，其余行按 YAML 解析。「YAML 配置」来源同样接受单个节点和节点列表。
  - 已有订阅：读取那个订阅上次下载的内容；不能引用另一个聚合订阅。
  - 节点里的锚点、别名和 `<<` 合并键会展开；来源自带的 `dialer-proxy` 指向它自己的组，会被去掉。
- **命名**：名称为空时用协议名；与代理组名、中转组名、`DIRECT` / `REJECT` 等内置策略或彼此重名时追加 ` 2`、` 3`……；`LANFLOW-` 前缀是澜流保留的，会被去掉。最多 5000 个节点。
- **代理组**按设置里的顺序生成（模块按目录顺序插入），中转组排在最后。模块目录在 `aggregate_catalog.go`，组名是「emoji + 名称」，例如 `🚀 节点选择`。各类型的成员：

| 类型 | 成员 |
| --- | --- |
| `🚀 节点选择`（必需） | 自动选择、有节点的地区组、中转组、全部节点、DIRECT |
| `🐟 漏网之鱼`（必需，MATCH） | 节点选择、DIRECT、自动选择、地区组、中转组 |
| 手动选择（select） | 节点选择、自动选择、地区组、中转组、DIRECT；设了节点筛选的自定义分组为匹配的节点 |
| 自动测速 / 故障转移 / 负载均衡 | 匹配筛选的节点（没有筛选为全部节点）；地区组即带筛选的自动测速组，没有节点时不生成 |
| 拦截 | REJECT、DIRECT、节点选择 |
| 直连 | DIRECT、节点选择、自动选择、地区组、中转组 |

  测速统一用 `https://www.gstatic.com/generate_204`、300 秒、`lazy: true`（url-test 容差 50，负载均衡 `consistent-hashing`）。

- **中转组**：select 组，成员是名称匹配「中转节点」正则的节点；名称匹配「落地节点」正则、且本身不是中转节点的节点写上 `dialer-proxy: <中转组>`。一个节点只接第一个匹配的中转组；没有匹配到中转节点的中转组跳过并警告。
- **规则**：自定义规则在前，然后是各代理组的规则集（按组的顺序）；同一条规则（同一规则集，或同一 `类型,值`）只保留第一次出现，所以自定义规则可以改写模块规则的目标。设置了「规则管理」的顺序时按它排列，未列出的规则跟在它原来的前一条后面；`MATCH,🐟 漏网之鱼` 总在最后。
  - 自带数据库（默认）：`geosite:x` 写成 `GEOSITE,x`；`geoip:` 的国家代码写成 `GEOIP,CC,…,no-resolve`，`private` 写成 `GEOIP,LAN`，`telegram` 换成它的 IP 段。`geoip.metadb` 只有国家，其余 IP 规则集（如 `geoip:google`）跳过：模块里的静默跳过，用户自己加的给出警告。启动内核不需要下载规则。
  - 远程规则集：每个规则集生成一个 `rule-providers` 项（`type: http`、`format: mrs`、每天更新），地址是「规则集 URL」（默认 MetaCubeX meta-rules-dat）下的 `geosite/<名称>.mrs` 或 `geoip/<名称>.mrs`；规则写成 `RULE-SET,geosite-x,…`。
  - 规则库列出的是自带 `geosite.dat` 的全部分类（`aggregate_ruledb_gen.go`，由 `go generate ./internal/profile` 从 `bin/geo/geosite.dat` 生成），加上常用国家代码和 meta-rules-dat 的几个 IP 服务集。
- **监听端口**：开启后每个节点一个 `mixed` 监听，端口从起始端口按节点顺序加一（不超过 65535），`proxy` 指向该节点，局域网设备可以直接用某个节点。
- **基础和 DNS 配置**：合并到配置顶层；`proxies`、`proxy-groups`、`rules`、`rule-providers`、`listeners`、`proxy-providers`、`sub-rules` 由生成器写出，这里的同名键忽略。之后仍按澜流的合成顺序叠加设置与覆写（[advanced.md](advanced.md)），所以澜流自己管理的端口、DNS 等会覆盖这里的值。
- **用量**：所有订阅链接来源的 `subscription-userinfo` 相加，到期取最早的一个。
- 生成的 YAML 里 emoji 保持原字符（编码器的 `\U…` 转义会还原），预览里看到的就是配置里的样子。

## 3. 模板

- 内置模板只决定代理组，与 SubBoost（v2.11）一致：分组目录共 36 个组、8 类；精简版 7 组 / 6 规则集（核心组）；标准版 14 组 / 21 规则集（核心组 + AI、油管、谷歌、微软、苹果、电报、代码托管）；完整版 33 组 / 91 规则集（除 Gemini、谷歌学术、成人内容外全部）。规则按 SubBoost 的全局顺序排列（如 Gemini 在 OpenAI 前、Apple TV+ 在苹果前），国内服务的完整列表 `cn` 排在「非中国」之后、不计入规则集数；远程规则集按 SubBoost 命名（`openai`、`cn-ip`）。旧配置中的地区组升级为按名称筛选的自定义分组，已合并的模块（Spotify、TikTok、Epic 等）迁到对应的新组。切换内置模板保留已有组的改名和改类型，以及自定义分组。
- 「保存为模板」保存当前设置里除来源、隐藏节点和节点顺序以外的全部内容（代理组、规则与顺序、规则来源、中转组、节点处理、监听端口、基础配置），存在 `aggregate-templates.json`，最多 50 个，只在本机。
- 「我的模板」套用时替换上述内容，来源、隐藏节点与节点顺序保持不变。

## 4. 版本与兼容

`AggregateSpec.Version` 为 2。第一版的设置（`autoGroup`、`regions`、`modules`）读出时自动升级：选中的地区与模块换成目录里对应的组，并加上第一版总会生成的私有网络与漏网之鱼。升级后组名带 emoji，代理页里原来选中的节点需要重新选择。

## 5. 更新与失败

- 「更新」「全部更新」和自动更新都会重新下载来源并重新生成；「全部更新」先更新链接订阅，再更新聚合订阅，所以引用已有订阅的来源能拿到刚更新的内容。
- 部分来源失败：照常更新，失败的来源这次不并入，订阅行显示 ⚠，悬停可见「已更新，但有 N 个来源失败：…」。
- 全部失败或没有剩下节点：更新失败，继续使用上次的配置。
- 生成的配置没有通过内核校验时与普通订阅相同：弹出「配置无法使用」对话框，旧配置保留。

## 6. 存储、同步与 agent

- 聚合设置存在 `profiles/<id>.aggregate.json`（`model.AggregateSpec`），生成的配置照常是 `profiles/<id>.yaml`；删除订阅时一起删除。模板存在 `aggregate-templates.json`。
- 聚合订阅和从文件导入的订阅一样**只在本机**，不写进 `lanflow.yaml`；同步时保留在本机。模板也不同步。
- 接口：`AggregateSpec`、`PreviewAggregate`（敏感读取）、`SaveAggregate`（写入）、`AggregateTemplates`（读取）、`SaveAggregateTemplate`、`DeleteAggregateTemplate`（写入）。返回给 agent 的聚合设置会去掉来源的链接和粘贴的 YAML（`redactAggregate`）；agent 提交时没带的按来源 ID 用已保存的补上（`keepAggregateLinks`）。

## 8. 暂不做

- 通过局域网向其他设备提供聚合后的订阅地址（SubBoost 的「生成订阅链接」），以及把生成的配置另存为文件（「下载配置」）。
- 模板广场（在线共享模板）。
- 并入来源里 `proxy-providers` 的节点。
- 配置同步。
